## 1. Executive Summary

A critical limitation identified in NR-056 is the extreme token starvation of ChakrView models ($\sim 624\text{K}$ tokens in Corpus V4), leading to near-zero generalization on unseen reasoning tasks. In compliance with NR-057 core constraints:
- **No external pretrained model weights** (e.g. HuggingFace GPT-2, Llama, Gemma, etc.).
- **No synthetic answers generated by external LLM APIs** (e.g. OpenAI, Anthropic, Gemini API).
- **All data must possess verifiable, transparent, permissive legal licensing** (Public Domain, CC-BY-SA, MIT/BSD/Apache, PSF-2.0).

This research audit evaluates prospective data sources, verifies their network accessibility and licensing compatibility, and establishes the formal ingestion blueprint for **Corpus V5**.

## 2. Permitted Source Catalog & Licensing Verification

### 2.1 Wikimedia Expository Extracts (English & Hindi)
- **License:** Creative Commons Attribution-ShareAlike 4.0 International (CC-BY-SA 4.0) and GFDL.
- **Content Type:** Expository encyclopedic prose across STEM (Physics, Chemistry, Computer Science, Biology, Mathematics), World Geography, History, Philosophy, and Linguistics.
- **Language Coverage:**
  - English (`en.wikipedia.org`): Multi-paragraph clean conceptual explanations.
  - Hindi (`hi.wikipedia.org`): High-quality Devanagari text covering national, scientific, and cultural knowledge, expanding ChakrView's Hindi lexical exposure.
- **Quality Filtering:** Disambiguation pages, meta-lists, edit-history noise, citations `[1]`, and non-prose tables are stripped. Documents with fewer than 200 characters are discarded.

### 2.2 Python Standard Library & Algorithmic Source Code
- **License:** Python Software Foundation License Version 2 (PSF-2.0, OSI-approved permissive open-source license).
- **Content Type:** Clean, idiomatic Python code, docstrings, and algorithmic modules (e.g. `collections`, `itertools`, `math`, `statistics`, `pathlib`, `json`, `heapq`, `bisect`, `dataclasses`).
- **Pedagogical Value:** Teaches structural indentation, syntax, typing annotations, docstring relationships, algorithmic procedures, and lexical consistency.
- **Quality Filtering:** Code is validated via Python `ast.parse` for syntax validity. Binary or auto-generated files are excluded.

### 2.3 Curated Internal Mathematical & Logical Proofs
- **License:** Public Domain / Creative Commons CC0.
- **Content Type:** Formal step-by-step mathematical proofs, arithmetic demonstrations, number theory, algebraic derivations, and propositional logic from `data/raw/mathematics/`.
- **Quality Filtering:** Formula balance check (matching parentheses, brackets, mathematical operator continuity).

### 2.4 High-Purity Local Foundation Corpora
- **License:** Internal ChakrView Curated / Apache-2.0.
- **Content Type:** High-quality non-contaminated segments of `data/raw/` and vetted Corpus V4 documents that passed strict deduplication and benchmark contamination checks.

## 3. Disallowed and Contaminated Sources

1. **Synthetic LLM Outputs:** Any dataset containing synthetic responses generated by proprietary frontier LLMs without human verification is rejected.
2. **Benchmark Test Datasets:** Any document overlapping with:
   - `fresh_heldout_benchmark_50.json` (NR-053)
   - `benchmark_v2_100.json` (NR-055)
   - `benchmark_v3_sealed_300.json` (NR-056)
   - Historical validation sets (`*_val.jsonl`, `*_dev.jsonl`)
   is strictly excluded via 13-gram MinHash and exact n-gram matching.
3. **Web-Scraped Boilerplate & Low-Quality Spam:** Unfiltered web crawls containing cookie banners, advertisements, navigation menus, and SEO link farms are banned.

## 4. Token Budget Projection & Reality Gate

While theoretical Chinchilla scaling recommends 340M+ tokens for 17M parameters, practical local training on an NVIDIA RTX A1000 6GB GPU must balance token ingestion speed, verified licensing, and storage throughput. 

In NR-057, we construct the initial **Corpus V5 expansion package** combining verified local human foundation corpora, algorithmic Python modules, and Wikipedia STEM/humanities expository collections. We rigorously measure the exact token yield using the canonical 4096 Byte-Level BPE tokenizer, documenting the exact gap toward 50M tokens without fabrication.
