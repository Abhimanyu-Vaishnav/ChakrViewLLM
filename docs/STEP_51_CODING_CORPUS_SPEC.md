## 1. Specification Overview & Core Axioms

The ChakrView Coding Corpus is a structured, project-aware data contract designed to enable causal language models to acquire programming syntax, module organization, cross-file relationships, and software engineering discipline.

### Core Data Axioms:
1. **The Project Boundary Axiom**: Source files never exist in isolation; they are elements of a bounded Project / Repository context.
2. **The Leakage Prohibition Axiom**: Splitting must occur at the **Project level**, never at the file or line level. All files belonging to Project $P$ must reside strictly in either the Training split, Validation split, or Test split.
3. **The Lossless Preservation Axiom**: Code formatting, indentation (tabs/spaces), line terminations, brackets, comments, and identifiers must be preserved without destructive truncation.
4. **The Quality Filtration Axiom**: Minified bundles, machine-generated locks, binary artifacts, and near-duplicates must be detected and excluded before tokenization.

## 4. Project-Level Split & Leakage Prevention Contract

Splitting rules:
- **Hash-Partitioning**: Each project is assigned a deterministic 64-bit integer hash:
  $$h(P) = \text{uint64}(\text{SHA256}(\text{project\_id})[:8])$$
- **Partition Assignment**:
  $$\text{split}(P) = \begin{cases}
  \text{train}, & (h(P) \pmod{100}) < 80 \\
  \text{val}, & 80 \le (h(P) \pmod{100}) < 90 \\
  \text{test}, & (h(P) \pmod{100}) \ge 90
  \end{cases}$$
- **Zero Cross-File Contamination**: Under no circumstances may a test file from Project $P$ appear in validation if its source files are in train.

## 5. Filtration & Quality Guardrails

1. **Binary & Non-Source Elimination**:
   - Files matching binary signatures (ELF, Mach-O, PE `.exe`, `.dll`, `.so`, `.dylib`, `.pyc`, `.wasm`, `.zip`, `.tar`) are discarded immediately.
   - Files with null bytes (`\x00`) in the first 8,192 bytes are rejected.

2. **File Size Boundaries**:
   - Minimum size: 10 bytes (eliminates empty or near-empty stub files).
   - Maximum size: 128 KB per file (avoids monopolizing context window with mega-files).

3. **Machine-Generated & Minified Code Filtering**:
   - Average line length $> 200$ characters: Filtered (flags minified JS/CSS).
   - Maximum line length $> 1000$ characters: Filtered.
   - Known auto-generated headers (e.g. `Generated by`, `DO NOT EDIT`, `@generated`, `autogenerated`): Quarantined.
   - Lockfiles (`package-lock.json`, `poetry.lock`, `Cargo.lock`, `yarn.lock`): Filtered from training text.

4. **Deduplication**:
   - **Exact Hash Deduplication**: Files with identical SHA-256 digests across different projects are deduplicated.
   - **MinHash / Jaccard Near-Deduplication**: Lexical 5-gram Jaccard similarity threshold set to $0.85$. If two files share $> 85\%$ n-gram overlap, the duplicate is excluded.

5. **Encoding Normalization**:
   - All files decoded via UTF-8 with NFC Unicode normalization.
   - CRLF line endings normalized to canonical LF (`\n`).
   - Trailing whitespace on lines stripped; terminal newline ensured.

6. **License & Provenance Guard**:
   - Only permissively licensed code (MIT, Apache 2.0, BSD-2/3, ISC, Unlicense, or indigenous ChakrView synthetic fixtures) is ingested.
   - Copyleft (GPL, AGPL) and proprietary/undocumented sources are blocked by the corpus ingestion gate.
