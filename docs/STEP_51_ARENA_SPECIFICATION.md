# ChakrView Step 51: Project Arena Specification

- **Document Version**: 1.0.0
- **Status**: Ratified Implementation Specification
- **Subsystem**: `chakrview/arena/`

---

## 1. Architectural Boundary & Security Model

The Project Arena provides a strictly confined, isolated execution environment for software projects generated by or evaluated by ChakrView.

### Non-Negotiable Security Invariants
1. **Never Execute in Host Process**: Generated code is **never** executed via `eval()`, `exec()`, or dynamic `importlib` inside the ChakrView process.
2. **Fail-Closed Subprocess**: All executions run in separate child Python subprocesses with mandatory timeout termination (`SIGKILL`/`terminate`).
3. **Strict Path Confinement**: All file reads, writes, and patch applications are verified against the canonical root of the workspace directory. Any path containing `..` or resolving outside the boundary raises `PathTraversalError`.
4. **Environment Sanitization**: Child processes run with an isolated environment:
   - `PYTHONPATH` points strictly to `workspace/source` and `workspace/tests`.
   - Host secrets, API keys, credentials, and tokens are scrubbed from `os.environ`.
5. **No Host Repository Access**: Subprocesses do not have `chakrview` in their `PYTHONPATH`. They cannot import ChakrView modules or read ChakrView checkpoints.
6. **Quota Enforcement**:
   - Max file count: 50 files (`WorkspaceQuotaExceededError`).
   - Max workspace size: 10 MB (`WorkspaceQuotaExceededError`).
7. **Process-Level Isolation Disclaimer**: Subprocess execution with timeout traps and environment scrubbing provides application-level containment. It does not provide kernel-level cgroups, Windows Job Objects, or hypervisor micro-VM isolation.

## 2. Workspace Directory Layout

Every project execution allocates an isolated workspace:

```
workspace/
├── project_manifest.json          # Root project manifest with metadata & file checksums
├── specification/
│   └── project_spec.json          # Task requirements, dependencies, timeouts, constraints
├── source/
│   ├── __init__.py                # Package initialization (role: INIT)
│   └── [source files]             # Implementation code (role: SOURCE)
├── tests/
│   └── test_[module].py           # Verification assertions (role: TEST)
├── runtime/
│   └── [configs/entrypoints]      # Runtime configuration (role: CONFIG)
├── logs/
│   ├── exec_[run_id].log          # Stdout and stderr logs
│   └── pytest.log                 # Detailed pytest execution trace
└── artifacts/
    ├── diffs/
    │   └── patch_[iter]_[file].diff # Unified diff patch files
    └── evaluation_report.json     # Final scoring and metrics
```

## 3. Data Contracts & Schemas

### 3.1 Project Specification (`specification/project_spec.json`)
```json
{
  "project_id": "proj_math_001",
  "project_name": "math_utilities",
  "description": "Basic arithmetic functions with clamp and safe division.",
  "language": "python",
  "version": "0.1.0",
  "license": "Apache-2.0",
  "dependencies": ["math"],
  "entrypoint": "core.py",
  "test_framework": "pytest",
  "timeout_seconds": 5.0
}
```

### 3.2 Source File (`SourceFile`)
- `path`: relative POSIX path within role directory.
- `content`: UTF-8 source string.
- `role`: `SOURCE`, `TEST`, `CONFIG`, `INIT`, or `DOC`.
- `sha256`: SHA-256 digest of `content.encode('utf-8')`.

### 3.3 Test Result (`TestResult`)
- `passed`: count of passed test cases.
- `failed`: count of failed assertions.
- `errors`: count of runtime or syntax errors.
- `skipped`: count of skipped tests.
- `duration_seconds`: execution wall time in seconds.
- `stdout` / `stderr`: full captured output.
- `exit_code`: process exit code (`0` = success, `1` = test failure, `-1` = timeout, `-2` = runtime crash).

### 3.4 Failure Classification (`FailureCategory`)
- `SUCCESS`: Exit code 0, all tests pass.
- `SYNTAX_ERROR`: Code fails AST parsing or Python compiler syntax check.
- `IMPORT_ERROR`: Module or symbol cannot be resolved.
- `ASSERTION_FAILURE`: Test condition evaluated to False.
- `TIMEOUT`: Execution exceeded `timeout_seconds`.
- `RUNTIME_ERROR`: Unhandled exception (e.g., `ZeroDivisionError`, `TypeError`).
- `SECURITY_VIOLATION`: Attempted path traversal or quota breach.

## 4. Lifecycle Operations

1. **Initialization (`IsolatedWorkspace`)**:
   - Creates directory tree.
   - Deepcopies manifest to preserve baseline files.
   - Writes specification and initial source/test files.
   - Verifies disk and file quotas.
2. **File Modification (`apply_patch`)**:
   - Asserts target path resides within `source_dir`.
   - Generates unified diff (`difflib.unified_diff`).
   - Writes patched file to disk.
   - Stores diff artifact in `artifacts/diffs/`.
   - Records `PatchDiff` in history.
3. **Execution (`SandboxedExecutor.run_tests`)**:
   - Invokes `pytest -v tests` in subprocess.
   - Sets timeout trap.
   - Parses stdout for test counters.
   - Extracts traceback diagnostic if failure occurs.
4. **Reset (`reset_to_initial`)**:
   - Clears `source/`, `tests/`, `logs/`, `diffs/`.
   - Restores files from deepcopied initial manifest.
   - Clears patch history.
5. **Teardown (`cleanup`)**:
   - Recursively deletes workspace directory (unless `preserve=True`).
