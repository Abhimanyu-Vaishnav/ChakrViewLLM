# Track B: Factual Recall and Evidence Grounding Audit

## Batches 1461–1500: Disentangling Parametric Recall from External Retrieval

### 1. Track Objective & Setup

Track B directly tests the origin of factual knowledge in ChakrView:
- Can the ChakrMicro neural network recall factual technical entities directly from its weights (**parametric memory**)?
- Or is factual question answering entirely dependent on the deterministic BM25 retriever and extractive verification pipeline (**grounded assistant**)?

**Dataset:** 40 precise technical factual questions (`fact_01` to `fact_40`) spanning storage architectures, network protocols, consensus algorithms, security credentials, and SLA parameters across the ChakrView technical documentation corpus.

**Compared Configurations:**
1. **Standalone ChakrMicro (No Retrieval, Weight-Only):** Prompted with the question and allowed to autoregressively decode up to 32 tokens.
2. **Local Knowledge Assistant (BM25 Retrieval + Extractive Verification + Answer Formatting):** End-to-end knowledge assistant runtime.
3. **Deterministic Reference Baseline:** Exact string match against indexed document chunks.

### 3. Detailed Error and Behavioral Analysis

#### A. Standalone Neural Core Behavior (0/40)
When asked direct factual questions without context, ChakrMicro exhibits classic small-model failure modes:
1. **Repetitive Formatting Traps:** On 32/40 questions, the candidate model emits `- Step-by-Step Solution:\nStep-by-Step S` or `The first of the first cannot the first...`.
2. **False Attributions:** In rare cases where it produces named entities, it hallucinated completely unrelated historical or religious names (e.g., `Christian And...` or `John 2008`).
3. **Zero Parametric Recall:** The model does not store or recall numeric constants (such as `k1=1.5`, `b=0.75`, `10485760 bytes`, `50 ms`, or `port 8443`) in its learned weights.

#### B. Grounded Knowledge Assistant Behavior (30/40)
When BM25 retrieval and extractive span selection are active:
1. **Accurate Factual Extraction (75.0%):** On 30 questions, the assistant retrieves the exact document chunk and extracts the factual span with valid markdown citations (e.g., `storage_bm25_index.md`, `network_consensus_raft.md`).
2. **Controlled Abstention on Ambiguity (10/40):** On the remaining 10 questions, where the retrieval query didn't exceed confidence thresholds or had minor lexical mismatches (e.g. `fact_35`, `fact_39`), the assistant cleanly abstained rather than hallucinating:
   `"I could not find sufficient verified evidence in the indexed local documents to answer this question."`
3. **Citation Integrity:** In 100% of answered queries, the cited file existed and contained the verifying evidence text.

### 4. Component Attribution Conclusion

$$\text{Factual Precision} = \mathbf{0.0\%} \text{ (Learned Weights)} \quad + \quad \mathbf{100.0\%} \text{ (Deterministic BM25 + Extractive Pipeline)}$$

- The ChakrMicro neural network possesses **no reliable standalone factual knowledge base**.
- All factual question-answering utility in ChakrView is generated by the **deterministic BM25 indexer, candidate search, extractive answer selector, and prompt formatter**.
- Any claim that "ChakrMicro knows the ChakrView architecture" is scientifically false; **the assistant's retrieval architecture knows the documents, while the model simply contributes token continuation**.
