## 3. Provenance and Scoring Flaw Audit (Batch 273 Requirement)

Inspection of `run_generalization_benchmark.py` and `answer_verifier.py` revealed several critical scoring flaws:
1. **Generic Substring Containment:** A validator checking if `exp in ans.lower()` allows false positives (e.g. if the query asks "What is 15 * 8?" and the model answers "1200", `"120"` matches as a substring).
2. **Superficial Code Validation:** Validating Python code solely by `ast.parse` or checking for `'def'` / `'input'` proves syntactic validity but does not prove the program actually performs the requested arithmetic task.
3. **Refusal Keyword Sufficiency:** Checking for `'insufficient'` or `'honest abstention'` allows a model that refuses *every* question to score 100% on unanswerable slices.
4. **Scoring Protocol Revision Plan:**
   - Word boundary / token exact matching for numbers (preventing substring false positives).
   - Constrained isolated execution in a sandboxed subprocess with assert checks for generated Python code.
   - Separate precision and recall metrics for abstention.
