# CR-EXP-15 Phase 1: Independent CR-14 Evaluator Audit

## 1. Executive Summary & Verification of Raw Predictions

An exhaustive audit of the CR-EXP-14 raw evaluation artifacts (`experiments/cognition/cr_exp_14_entity_binding/eval_outputs/*.json`) was conducted to evaluate the mathematical and logical validity of the reported metrics across all six evaluated models (CR-11 Candidate A, CR-12 Candidate A, CR-12 Candidate B, Candidate A, Candidate B, Candidate C).

Every reported metric from CR-EXP-14 was independently recomputed from the raw model generation strings.

---

## 2. Forensic Answers to the Core Audit Questions

### Question 1: Why did all six models have exactly 8.33% subject accuracy?
- **Finding:** In the CR-14 benchmark, exactly $100$ out of the $1,200$ probes belonged to the category `missing_information_abstention`.
- In `experiments/cognition/cr_exp_14_entity_binding/scripts/evaluate_sealed_benchmark.py` (line 97):
  ```python
  if cat == "missing_information_abstention":
      is_strict_hit = is_abstained
      is_value_hit = is_abstained
      has_subj = True  # Not applicable to abstention
```
- Because `has_subj` was hardcoded to `True` for all $100$ abstention probes and evaluated to `False` on all $1,100$ non-abstention probes across all six models, the subject accuracy numerator was identically $100$ across every model:
  $$\text{Subject Accuracy} = \frac{100}{1200} = 8.3333\% \approx 8.33\%$$
- On the $1,100$ answerable state-tracking probes, **actual subject accuracy was 0/1,100 (0.00%) for all six models**.

### Question 2: Why do overall strict hits equal correct abstentions?
- **Finding:** Across all six models, the number of strict hits on Categories 1 through 6 (the 1,100 state-tracking, recency, multi-entity, and counterfactual probes) was identically **0**.
- Therefore, any "strict hit" registered in the entire benchmark occurred *solely* from Category 7 (`missing_information_abstention`), where `is_strict_hit = is_abstained`.
  - CR-11 Candidate A: 60 abstentions $\to$ 60 strict hits ($60/1200 = 5.00\%$)
  - CR-12 Candidate A: 100 abstentions $\to$ 100 strict hits ($100/1200 = 8.33\%$)
  - CR-12 Candidate B: 100 abstentions $\to$ 100 strict hits ($100/1200 = 8.33\%$)
  - Candidate A: 23 abstentions $\to$ 23 strict hits ($23/1200 = 1.92\%$)
  - Candidate B: 33 abstentions $\to$ 33 strict hits ($33/1200 = 2.75\%$)
  - Candidate C: 88 abstentions $\to$ 88 strict hits ($88/1200 = 7.33\%$)

### Question 3: Does subject accuracy check the queried entity or merely detect any subject name?
- In `evaluate_sealed_benchmark.py` (line 85):
  ```python
  has_subj = subj.lower() in gen.lower() if subj else False
```
- The code correctly searched for the specific queried subject (e.g. `abhay` in generation). It did *not* reward unrelated training names.
- However, by setting `has_subj = True` for abstention probes, the aggregate metric combined answerable subject identification with unanswerable abstentions into an unsegmented denominator ($1,200$).

### Question 4: Does strict correctness require the exact subject-value association?
- In line 107:
  ```python
  is_strict_hit = (
      has_subj and has_tgt and not has_stale and not has_distractor
  )
```
- On natural language generation without syntactic parsing, checking `has_subj and has_tgt` confirms that both tokens appear in the output string. In our diagnostic testing, when the model generated `'Assistant: Ashesh is currently in Aur'`, neither the queried subject (`Abhay`) nor the expected city (`Dhanbad`) was present.

### Question 5: How are stale and distractor values penalized?
- Stale values and distractors were penalized via string exclusion (`not has_stale and not has_distractor`). Since neither target, stale, nor distractor cities from the sealed benchmark were generated by any model, this branch was never falsely triggered.

---

## 3. Discovered Flaws in the CR-14 Evaluator & Design

1. **Denominators Conflation:** Combining $1,100$ answerable capability probes with $100$ negative abstention probes into a single $1,200$ aggregate metric obscures the true capability profile.
2. **Monolithic Task Packaging:** In CR-EXP-14, the benchmark combined multi-turn state tracking, long context, entity copying, and city retrieval simultaneously into single multi-turn prompts. If a model fails to copy an unfamiliar multi-token name, it automatically scores $0\%$ on state tracking even if it could theoretically track positional updates or identify entities.
3. **Absence of Atomic Capability Deconstruction:** CR-14 could not determine *where* in the cognitive pipeline the failure occurs:
   - Does it fail at **copying** unfamiliar names?
   - Does it fail at **selecting** the queried subject from a small set?
   - Does it fail at **static binding** of 1 entity $\to$ 1 value?
   - Or does it fail specifically at **dynamic overwriting / state updating**?

---

## 4. Remediation for CR-EXP-15
In CR-EXP-15:
- We formulate an explicit capability decomposition separating copying, selection, static binding, dynamic updates, and abstention into isolated, independently scored tasks.
- We report all numerators and denominators explicitly. Abstention precision/recall is kept strictly separate from answerable state tracking.
